## 1. 决策：三 Agent 角色与能力路由

- **Decision**: 实现三个独立逻辑 Agent 角色——查询规划 Agent（识别意图、拆解子问题 `sub_problem_id`、选择检索信号与关系方向，蓝图 §11.1）、证据分析 Agent（覆盖度/缺口/冲突结构化判断，蓝图 §11.2）、上下文编排 Agent（去重、保多样、父级补充、节点 Schema 输出，蓝图 §11.3）。实际模型由能力路由层选择：查询规划（简单、高频）倾向**低延迟模型**，证据分析（复杂证据判断）倾向**更强模型**，上下文编排居中可配（spec FR-002、Assumptions、蓝图 §11 末段、§18.4）。
- **Rationale**: 三角色职责正交、可独立 Schema 校验与降级（FR-003）；能力路由允许简单角色省成本、复杂判断保质量，且不绑定具体 LLM 供应商（宪法架构约束、§18）；保留三角色不因理论超时提前合并（蓝图 §19）。
- **模型/Prompt 选型**: 默认模型路由——查询规划与上下文编排走**本地低延迟 LLM**（与 bge-m3/bge-reranker 同源本地优先策略），证据分析走更强模型（如 DeepSeek V4-Flash，蓝图 §18.4）；具体模型名与 Prompt 模板在运行配置声明并记录于 `model_and_version` 元数据；005 规格不绑定具体模型版本（避免实现细节泄漏），只约束角色职责、Schema 校验与降级（FR-002/FR-003）。
- **Alternatives**:
  - 单一全能 Agent：违背蓝图 §11 三角色正交与可独立降级，且单点失败即全链路阻塞，拒绝。
  - 提前合并角色以降延迟：蓝图 §19 明确"三个 Agent 均保留，不因理论超时提前合并；实际优化依据真实评测"，拒绝。
  - 绑定单一供应商：违反宪法架构约束"不绑定具体 LLM 供应商"（§18），拒绝。

## 2. 决策：LangGraph 确定性状态机与补充检索有界循环

- **Decision**: LangGraph 管理状态机与节点流转，LangChain 提供模型/Prompt/Retriever 适配；状态跳转权属于确定性控制器，不属于 Agent（蓝图 §12、宪法 VI）。主状态流为蓝图 §12 九步；**补充检索为有界循环**：证据分析（步骤 6）输出缺口且确定性控制器决定继续时，查询规划 Agent（步骤 3）携带缺口上下文重新生成补充检索查询，召回候选重新进入步骤 4（并行检索）→5（融合与 Rerank）→6（证据分析），使每轮补充召回证据携带融合/Rerank 分数并经证据分析 Agent 重新评估覆盖度，直至无缺口或达最大检索轮次后进入步骤 8（上下文编排）；一个检索轮次 = 查询规划（补充）+ 检索 + 融合 + Rerank + 证据分析（spec FR-005/FR-014）。
- **护栏固化**（spec FR-006 澄清）：最大检索轮次默认 2（首轮 + 至多 1 次补充）/上限 3；Agent 节点超时默认 5s/上限 10s；最终上下文装箱上限沿用 001（top_k ≤ 20）；单来源最大证据数默认 3/上限 5（005 新增固化）；总超时沿用 30s 并 < 目标 Host 最低 Tool Call 超时；每路召回与 Rerank 候选沿用 002 实现值；图扩展跳数默认 2/上限 3、候选预算默认 10/上限 20、查询子超时 3s 沿用 004 固化值（spec FR-033）。护栏作为运行配置可覆盖但不得超上限。
- **Rationale**: 有界循环使补充召回证据"重新过融合/Rerank/分析"而非直接并入上下文，保证排序可解释、可重复（SC-008/SC-009）；护栏固化避免无界迭代与延迟失控；查询规划携带缺口上下文重新被调用，缺口驱动而非 LLM 独占状态机跳转（宪法 VI）。
- **Alternatives**:
  - 补充候选直接并入上下文编排（跳过融合/Rerank/分析）：违背"每轮证据携带融合/Rerank 分数并经重新评估"（spec 澄清），排序不可解释，拒绝。
  - LLM 独占"是否继续检索"决策：违反宪法 VI（确定性控制器决定），拒绝（spec FR-013/FR-015）。
  - 无界补充循环：延迟与成本失控，违背 §12 护栏，拒绝。

## 3. 决策：追加式证据账本与标识契约

- **Decision**: 原始证据使用**追加式账本**（`evidence_ledger_entry` 表），Agent 可引用/评价/筛选但不得覆盖原始检索记录（FR-008）。固化标识契约（spec FR-032）：账本条目 `ledger_entry_id`（雪花 ID `^[0-9]+$`，与 `chunk_id`/`knowledge_scope_id` 同型）；查询规划拆解子问题以 `run_id` 内单调递增 `sub_problem_id` 标识；补充检索轮次以 `run_id` 内单调递增 `round_index` 标识（round_index=0 为首轮）；每条账本条目携带 `sub_problem_id` 与 `round_index`，使 SC-009"按拆解子问题分组追溯证据"可在账本中聚合。上下文编排结果以 `run_id` 内稳定 `context_result_id` 标识，并以**独立追加式选择清单**（`{context_result_id, ledger_entry_id, decision: selected|truncated|deduped}`）记录选中/截断/去重决策，不改写原始账本条目（FR-017）。Agent 角色标识 `{query_planner, evidence_analyst, context_orchestrator}`。
- **Rationale**: 追加式 + 独立选择清单保证"Agent 筛选不改原始记录"不变量（FR-008/SC-006）；雪花 ID 与既有标识同型保证全链路可定位（宪法 IV）；`sub_problem_id`/`round_index` 使"为何返回这条证据"可按子问题与轮次解释（蓝图 §13、SC-009）；选择清单的 `decision` 枚举使上下文编排去重/截断可审计。
- **对外契约不变**: 001 `search_knowledge` 输出 Schema 的 evidence 项为 `additionalProperties: false`，005 **不**向其新增字段（FR-024，宪法 VII）；账本引用与 Agent 判断为**内部追踪契约**，以输出中的 `request_id`（001 已有）+ `evidence_id`（001 已有）为桥接键对外可追溯——运维/评测可凭 `(request_id, evidence_id)` 解析内部账本，外部 Agent 无需账本字段即可消费（spec Assumptions）。
- **Alternatives**:
  - 向 MCP 输出 evidence 项新增 `ledger_ref` 字段：违反 `additionalProperties: false` 与 FR-024"不修改对外契约"，拒绝。
  - 账本可改写：违背 FR-008 追加式不变量与 SC-006，拒绝。
  - UUID 标识：与 `chunk_id` 雪花数值串模式不一致，跨存储关联更繁，拒绝。

## 4. 决策：证据充分性混合机制与终态降级

- **Decision**: 证据判断采用混合机制（蓝图 §14）——硬指标（有效来源数、Rerank 分数、版本有效性、项目作用域、未解决冲突）+ 证据分析 Agent 结构化判断（覆盖度状态枚举 `{covered, partial, uncovered}`、冲突类型枚举 `{none, version_conflict, source_conflict, domain_conflict}`、未覆盖子问题标识、是否需要补充检索）共同支撑，**确定性控制器决定终态**与"继续检索或进入返回阶段"（FR-013/FR-015，宪法 VI）。终态沿用 001 四态 `complete`/`partial`/`no_evidence`/`failed`；`partial` 携带已验证证据、未覆盖问题、冲突与失败路径（FR-016）。当某 Agent 结构化输出未通过节点 Schema 校验、节点超时或 Agent 编排被运行配置关闭时，系统回退到该角色/路径的**确定性等价行为**并仍返回有效四态，不因 Agent 失败而无法响应（SC-011）。
- **Rationale**: 混合机制使判断既有确定性硬指标兜底又有 LLM 语义判断增益，且控制权在确定性控制器（宪法 VI）；四态可区分可操作沿用 001；降级路径保证 Agent 失败不阻塞确定性检索（蓝图 §19、Edge Cases）。
- **Alternatives**:
  - LLM 独占终态决策：违反宪法 VI，拒绝。
  - Agent 失败即整体 failed：违背 SC-011 可降级要求，拒绝。
  - 以生成内容填补缺口：违反宪法 III（暴露不确定性），拒绝。

## 5. 决策：上下文编排

- **Decision**: 上下文编排 Agent 基于已选证据组织外部 Agent 可消费的上下文——消除重复内容、保留来源多样性、决定父级上下文补充范围、输出符合节点 Schema 的编排结果，并受最终上下文装箱上限约束（top_k ≤ 20）；超量时保留最高相关可定位证据并为被截断证据提供可展开证据 ID（FR-017/FR-018，蓝图 §11.3）。编排结果以 `context_result_id` + 追加式选择清单（§3）记录，不改写原始账本。
- **Rationale**: 去重/多样/父级补充使最终上下文精简且可消费；装箱上限沿用 001 保证响应大小可控；选择清单使去重/截断可审计（SC-006）。
- **Alternatives**: 无上限装箱：违背 §12 护栏与 001 超量截断策略，拒绝；上下文编排改写账本：违反 FR-008，拒绝。

## 6. 决策：提示注入防护与数据控制分离

- **Decision**: 上传材料与检索内容始终视为不可信数据；原始内容只进入证据字段，控制指令与证据内容使用结构化边界隔离；检索文本不得直接控制状态机跳转、工具调用或模型权限；可疑提示注入内容检测并标记；高风险片段可从内部控制 Prompt 隔离但仍保留可审计来源；Agent 结构化输出必须通过节点 Schema 校验（FR-019/FR-020，蓝图 §15、宪法 V）。Agent 推理结果不自动写回项目知识库（FR-011，蓝图 §20）。
- **Rationale**: 结构隔离是安全边界，风险检测为辅助（蓝图 §15）；Schema 校验使 Agent 输出不得逃逸为控制指令（宪法 V/VI）；不写回知识库防止运行状态污染项目事实（蓝图 §20）。
- **Alternatives**: 仅靠风险检测不做结构隔离：蓝图 §15 明确"风险检测是辅助，结构隔离才是安全边界"，拒绝。

## 7. 决策：状态隔离、运行状态 TTL 与追踪可关闭

- **Decision**: LangGraph 状态按 `request_id` 与 `run_id` 隔离；不保存全局活动项目或隐式会话状态；每个请求独立携带 `project_scope`（FR-025，蓝图 §21.1）。Agent 运行状态与追踪记录使用 TTL；追踪配置允许关闭查询正文与证据正文记录，只保留 ID、状态、耗时与错误（FR-011/FR-012，蓝图 §20）。运行状态不进入向量库（蓝图 §20）。
- **Rationale**: 请求级隔离沿用 001 SC-008（5 并发不串扰）；TTL 防止运行状态无限增长；追踪可关闭正文保护敏感内容（蓝图 §20）。
- **Alternatives**: 全局活动项目：违反宪法 I 与蓝图 §21.1，拒绝；运行状态永久保存或写回知识库：违反蓝图 §20，拒绝。

## 8. 决策：能力路由层与 Provider 接口

- **Decision**: 后端使用 Model Gateway 与能力路由层，不绑定具体 LLM 供应商；能力维度包括结构化输出、复杂推理、长上下文、成本、延迟、超时与降级（蓝图 §18）。OpenAI/Anthropic-compatible 仅作供应商适配协议，不替代内部统一能力契约。三 Agent 各自经能力路由选模型（§1）；Embedding/Reranker 复用 001/002 的 `BAAI/bge-m3`/`BAAI/bge-reranker-v2-m3`。
- **Rationale**: 复用既有 Provider 抽象避免新依赖；能力维度驱动而非供应商驱动，符合宪法架构约束。
- **Alternatives**: 硬编码单一供应商：违反 §18，拒绝。

## 9. 决策：目标 Host 兼容性

- **Decision**: 沿用 001 参考客户端策略——DeepSeek Harness 为本机已安装的必过参考客户端（Agent 编排 `search_knowledge`/`get_evidence` 端到端调用与输出 Schema 校验 MUST 通过，SC-012）；ChatGPT App 与 Claude Code 记录兼容性状态、MUST NOT 作为 005 验收阻塞项。Agent 路径 30s 总超时护栏 MUST < 三端最低 Tool Call 超时预算，超时则降级 `partial`（蓝图 §19，spec 澄清）。
- **Rationale**: 005 不修改 001 已确立的 MCP 对外契约（FR-024，宪法 VII）；Agent 判断与账本引用为内部契约，通过 `request_id` 桥接（§3）。
