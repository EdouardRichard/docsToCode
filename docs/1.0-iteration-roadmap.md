## 1. 001 现状盘点（迭代 0 的依据）

### 1.1 已实际落地（代码存在，可运行）

- **后端骨架**: FastAPI 管理面（`server.py`）+ async SQLAlchemy（`db.py`）+ Alembic 3 个迁移（`001_initial` + 2 个修复迁移）。
- **7 个 ORM 实体**: knowledge_scope / project / knowledge_source / knowledge_version / chunk / processing_run / retrieval_run 全部存在。
- **解析器**: `credential_redactor`、`markdown_parser`（markdown-it-py 章节切片）、`java_parser`（tree-sitter 符号切片）均实现。
- **Provider 抽象**: `base.py`（Embedding/Reranker/LLM 三个 ABC）+ `local_cpu.py`（bge-m3，1024 维，lazy load）。
- **入库管线**: `ingestion_service.py` 已实现 redact→parse→embed→Qdrant upsert→版本发布→旧版本 supersede 的完整闭环。
- **检索管线**: `retrieval_service.py`（作用域+版本过滤、top_k、per-source 限制、四态 completion_status）+ `evidence_service.py`（作用域校验、父级补全）。
- **MCP 双 Tool**: `search_knowledge` + `get_evidence` 注册于 FastMCP Streamable HTTP（`mcp/__init__.py` + `_run_mcp.py`），当前会话已实际连通（`mcp__rag-mcp__*` 工具可用）。
- **管理 API**: projects / knowledge_sources（含 reprocess、delete、clear）/ sse 路由 + 请求隔离中间件。
- **前端**: Vite+React+TS+antd，ProjectsPage / ProjectDetailPage / useSSE / api client 存在。
- **评测脚本**: `eval/generate_dataset.py` + `eval/run_eval.py`（Recall@K / MRR / nDCG / P50/P95）。
- **测试**: unit / integration / contract 三层大量用例已写。

### 迭代 1 — 002 Hybrid Retrieval Precision

**蓝图依据**: §23.4.2、§9（混合检索）、§18.2（BGE-M3 Dense+Sparse）、§8.1（Qdrant BM25/RRF）。

**任务**:
1. 启用 Qdrant Sparse/BM25 索引（bge-m3 sparse 向量或 Qdrant 原生 BM25 tokenizer），扩展 `index_version` 能力清单为 `dense_ready + lexical_ready`。
2. 实现 RRF/DBSF 融合（确定性融合层），公共/项目知识域身份在融合后保留（§9）。
3. 落地 `RerankerProvider`：`BAAI/bge-reranker-v2-m3`（local CPU 默认），只对融合后有限候选 rerank。
4. 扩展 KnowledgeVersion 能力声明与查询规划（只调用已发布版本声明的能力，§5）。
5. 评测对照：在固定评测集上产出 002 混合检索 vs 001 Dense 的 Recall@K/MRR/nDCG/P50/P95 对照报告；**未证明收益且不违反硬指标，不得进入默认路径**（§24.3）。

**验收**: 混合检索对照报告产出；`lexical_ready` 版本发布链路闭环；BM25 命中固定类名/错误码/字段名能力验证；三硬指标不回归。

### 迭代 2 — 003 Structured Asset Expansion

**蓝图依据**: §23.4.3、§7（格式感知切片）、§2.1（范围内格式）。

**任务（按独立验收批次，每批独立闭环）**:
- 批次 A: OpenAPI/Swagger（按 service/endpoint/request/response/schema 切片）。
- 批次 B: DDL（按表/字段/约束/索引/视图/存储过程切片）。
- 批次 C: Word + PDF（标题/段落/列表/表格结构切片，检索安全副本+凭据规范化）。
- 批次 D: Go + Python（AST 符号切片，复用 tree-sitter）。
- 每批扩展 `format` CHECK 约束、parser、chunk_type、评测集补充与来源定位路径。

**验收**: 每批新增格式的「上传→切片→检索→证据定位」端到端通过；跨格式评测集 Recall 不劣化；凭据规范化在非代码格式同样生效。

### 迭代 3 — 004 Graph RAG

**蓝图依据**: §23.4.4、§10（双层图谱）、§8.2（PostgreSQL 图关系 + 递归 CTE）。

**任务**:

**验收**: 图关系可追溯（每个边有证据来源）；硬/软关系在 MCP 响应中可区分；一至三跳扩展延迟可接受；对照报告证明收益。

### 迭代 4 — 005 Agentic Retrieval Orchestration

**蓝图依据**: §23.4.5、§11（三 Agent）、§12（确定性状态机/LangGraph）、§13（证据账本）、§14（证据充分性四态）。

**任务**:
1. 真正落地 LangGraph 状态机（节点流转权归确定性控制器，Agent 只出结构化判断），实现主状态流（§12 步骤 1–9）。
2. 三 Agent 逻辑角色 + 能力路由层（简单角色低延迟模型、复杂判断强模型，DeepSeek V4-Flash 用于复杂语义，§18.4）。
3. 追加式证据账本：每条证据记录查询/检索器/得分/版本/来源/轮次，Agent 不可覆盖原始记录。
4. 缺口驱动补充检索（最大轮次护栏）+ 上下文编排（去重/来源多样性/父级补全/装箱上限）。
5. 提示注入防护结构化边界（§15）+ 节点专属 Schema + Schema 校验。
6. 与 001 确定性基线对照评测，证明收益后进入默认路径。

**验收**: 四态（complete/partial/no_evidence/failed）语义完整；证据账本可解释「为何返回此证据」；补充检索在护栏内收敛；注入防护与 Schema 校验通过。

### 迭代 5 — 006 Runtime Hardening

**蓝图依据**: §23.4.6、§19（延迟/降级）、§20（运行状态保留）、§21（实例/并发）。

**任务**:
1. 单写多读：`WriteCoordinator` 抽象 + PostgreSQL 单 Writer 租约（误启第二个 Writer 拒绝写模式）；`reader` 只读 MCP 检索连共享 Qdrant/PG。

**验收**: writer/reader 两模式端到端；租约防双写生效；provider 切换重建索引版本；追踪脱敏可关闭；超时/降级（partial 语义）在目标 Host 超时约束下工作。

## 3. 跨迭代铁律（每轮都须遵守）

1. **评测驱动**（蓝图原则 10 / §24.3）: 002/004/005 的增强能力，只有在固定评测集上证明收益且不违反三硬指标后，才能进入默认检索路径；每次进入 `plan.md` 前必须在 `research.md` 声明相对基线目标。
2. **硬指标三件套**（§24.2）: 跨项目串库 = 0、Schema 合法率 = 100%、来源可定位率 = 100%，任何迭代不得回归。
3. **显式项目作用域**（原则 1）: 无 `project_scope` 一律拒绝全库检索，贯穿所有 Feature。
4. **接口独立演进**（原则 7）: DB 模型 / 内部 Agent 状态 / MCP 契约解耦；内部 Agent Schema 不复用 MCP 对外 Schema（§22）。
5. **知识版本不可混用**（原则 8）: 换 Embedding 模型/切片策略必须新建 `index_version` 与集合，重新向量化。
6. **范围外不提前做**（§26）: Neo4j、MCP Tasks、OAuth/认证、自动同步、广义脱敏、自动回写知识库，仅在触发条件满足后进入新 Feature。

## 4. 建议执行节奏

- **先硬后软、先确定性后 Agent**: 迭代 1（混合检索）和迭代 2（格式扩展）可并行；迭代 3（Graph）依赖迭代 1；迭代 4（Agent）依赖 1/3 的确定性基线；迭代 5（加固）可与 2–4 并行推进。
- **每轮一个 specKit 循环**: 每个 Feature 走 Constitution → Specify → Clarify → Plan → Checklist → Tasks → Analyze → Implement → Converge（蓝图 §23），产物用 `tasks.md`（非 todo.md）。
- **门禁**: 迭代 0 是总门禁——001 未固化前不进入任何增强 Feature，否则缺乏可对照的 Dense 基线。
